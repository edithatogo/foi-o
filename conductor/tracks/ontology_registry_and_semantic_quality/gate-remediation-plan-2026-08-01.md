# Ontology registry gate-remediation plan

## Current blockers

The local ontology and semantic-quality implementation is validated. The
remaining blockers are outside repository-local proof:

- namespace migration approval;
- external ontology registry submission;
- ontology publication;
- profile or semantic promotion; and
- external repository mutation.

## Options

### Option A — retain validated local registry state (recommended)

Keep the current namespace migration and registry ledger local, preserve the
quality report and hashes, and prepare a submission packet without submitting
it. This is reversible and preserves the human certification boundary.

### Option B — authorize namespace migration

Approve an exact migration revision, compatibility alias policy, affected
consumers, and rollback evidence. This does not authorize publication or
registry submission.

### Option C — authorize registry or ontology publication

Approve one named destination, exact artifact and registry hashes, rights and
attribution terms, and the single upload or submission operation. A successful
local validator is not publication authorization.

### Option D — authorize semantic/profile promotion

Approve the exact profile or ontology revision, evidence scope, independent
quality review, and promotion decision. Promotion remains separate from
publication.

## Recommended sequence and contingencies

1. Retain Option A while the local quality report remains current.
2. If migration is desired, review and approve the exact compatibility packet.
3. Recompute quality and hashes after any semantic change.
4. Submit or publish only the approved exact packet to the named destination.
5. If rights, labels, namespace compatibility, or hosted checks fail, retain
   the candidate status and record a rejection receipt.
6. Archive only after the track's human gate and acceptance criteria are
   explicitly complete.
